# 参考文献自动提取工具

输入文件后，程序独立完成读取、参考页选择、阅读顺序恢复、分条、检查及输出。默认先尝试规则，检查不足时回退原模型流程。运行不需要页码、坐标、预期引用数或人工分好的列表。

给他人讲解时可打开 [逐步流程与分支示例网页](../docs/design/reference-extraction/index.html)，包含交互演示、与“读清引用”设计阶段的对应关系和真实输出链接。

## 使用

在仓库根目录运行：

```powershell
.\run-reference-extractor.ps1 -InputFile '你的参考文献材料.pdf'
```

也可以指定一个尚不存在的输出目录：

```powershell
.\run-reference-extractor.ps1 -InputFile '你的参考文献材料.pdf' -OutputDirectory 'output\my-first-run'
```

脚本优先使用本项目虚拟环境、当前机器可用的 bundled Python，或已安装所需依赖的系统 Python。`.env` 已配置模型地址，密钥由用户本地填写。不同终端的同名环境变量不会隐式覆盖这个程序显式读取的 `.env`。

其他机器可以先在虚拟环境安装依赖，再从仓库根目录运行：

```powershell
python -m pip install -r requirements-reference-extraction.txt
python -m reference_extractor '你的材料.pdf'
```

## 输入支持与边界

- 文字 PDF：直接读取文字块和坐标，规则优先定位和分条；不确定时回退模型。独立 CLI 的模型路径可以使用页图，网页应用沿用文字路径，避免额外视觉调用。
- 图片、扫描 PDF：Qwen 转写原图，再进行来源分条。没有使用 PaddleOCR。
- 普通 DOCX：按文档顺序读段落和表格；图片、文本框或修订结构明确拒绝并提示转换。自动编号的显示数字未保证保留。
- UTF-8 TXT：逐个非空行建立来源。
- 单个输入文件；PDF 不设总页数上限。模型回退路径选中参考页最多 8 页；规则路径不受这一模型页数限制。文字与扫描混合或含空白页的 PDF 暂不支持；超限明确失败。
- 若全文未能识别参考页或没有引用，不输出“成功但 0 条”。

## 完整处理链

1. 创建新的运行目录，复制输入快照，记录 SHA256 和代码摘要。
2. 提取带位置的原文块；扫描件/图片先经模型转写。
3. 规则提出参考区域：标题、行首编号、连续的书目信息、重复缩进/分栏；支持编号和保守的无编号悬挂缩进路径。
4. 检查编号连续性、条目书目特征、可疑段落边界、区域外其他书目编号，以及来源覆盖。跨栏分组使用各栏自己的缩进基线；保留原始编号和原始文字。
5. 规则通过后不调用模型选页、分组、排除复核；原始块全部归到引用或带理由的排除项。规则检查是启发式，不是正确性证明。
6. 规则不通过时，沿用模型选页、来源编号分组、排除项复核流程；不合格最多尝试两次，保留全部尝试。本轮尚未做局部模型修复，也未接入 GROBID 或第二阅读器作为生产回退。
7. 规则路径按自身阅读顺序输出，模型路径沿用原坐标排序；无坐标输入使用来源顺序。
8. 程序拼接原始文字，写出 HTML、TXT、JSON 和所有中间记录。

列排序使用通用的引用起点横坐标聚类，间距阈值为页面归一化宽度的 180/1000，不包含论文专用坐标。复杂跨栏、居中条目及非常规排版仍需进一步测试；排序记录单独保存。

图片转写默认只要求逐行文字与不确定性，不要求模型生成坐标，以避免虚构或越界坐标。视觉模型原生的 `[{text,bbox_2d}]` 形态仍可由固定适配器转换；如果返回坐标则必须合法。转换不改文字；没有明确不确定性字段的转写保守标记待复核。引用分组中的字符串条目不接受，必须通过结构校验或重试。

## 输出

每次运行产生独立目录，原结果不覆盖：

- `index.html`：完整引用列表、来源页、排除文字和疑点，可直接本地打开。
- `references.txt`：可读引用列表。
- `result.json`：状态、引用、来源 ID、哈希、用量和耗时。
- `input.*`：本次输入快照。
- `source-blocks.json`：提取/转写的原文块。
- `rules-analysis.json`：规则版本、候选区域、每条特征、边界及未通过的检查。
- `page-selection.json`：选页结果及理由。
- `partition.json`：最终来源分组；模型路径另有 `partition-initial.json`、`exclusion-audit.json`。
- `reference-order.json`：模型初始顺序与程序最终排序。
- `pages/`：程序渲染的整页与必要的转写结果。
- `api/`：每次请求的提示、原始回复、验证结果及用量；不保存请求鉴权头。

“流程完成”仅表示程序执行与校验通过，不保证选页、转写或文献真伪正确。规则路径覆盖全输入已读块，模型路径覆盖所选页；两者都不能证明没有误排除或 OCR 没漏字。识别疑点保留为“需要复核”，API/格式/覆盖最终失败记为“执行未完成”。

可用 `python -m reference_extractor 文件.pdf --mode model` 保留原模型提取方式做对照。网页应用新任务自动使用规则优先，不改查询及身份核验；旧任务代码快照保持不变。

2026-10-22 的 53 条真实文件对比见 [对比网页](../experiments/reference_extraction/2026-10-22-rules/comparison-02/index.html)。新提取不读取旧结果；旧结果只在提取后参与评估。另用 pypdf 检查编号与原文，未引入生产依赖。

随后使用43份真实PDF做压力测试并修复通用问题，详见 [批量测试报告](../experiments/reference_extraction/2026-10-22-stress/index.html)。新规则加入栏间空白、字号、机构署名、历史年份和页脚检查；原文读取保留下标顺序。实际读取器/模型回退、超页数等边界在报告中分开记录，规则通过率不等于准确率。

## 测试

```powershell
python -m unittest discover -s tests -v
```

测试覆盖原文遗漏、重复、未知 ID、越界页码、无效识别坐标、原生视觉返回结构适配、流输出截断、自动重试、错误记录、栏顺序、排除复核和命令核心输出。真实 PDF/图片运行记录与人工评价分开保存，评价数据不作为运行输入。


### 2026-10-22 泛化修复

- PDF 不设总页数上限；逐页释放读取缓存，保留物理页码和原文块。不再按全文6000块拒绝。
- 参考文献标题候选优先；支持数字及字母标签、局部字号提示、视觉行碎片顺序、机构作者与年份字母后缀。
- 字号或主题词只能提示终点，不能单独批准排除后文。只有终点歧义时可小范围模型复核；远处仍有书目线索时放弃捷径。
- 模型选页按每批180000字符处理；有依据且前缀没有书目/署名线索时才缩小范围，保留标题后的所有页，不相信未经确认的结束页。
- 模型选页与规则候选、区域外标签和其他参考标题交叉检查；冲突标待复核。模型分组中的短/弱证据、作者碎片、文章自身Citation栏均保留待复核，不自动判假或删除。
- 剩余模型分组页数/块数预算、扫描与复杂Word限制仍独立存在。规则和模型均非完整性证明。
